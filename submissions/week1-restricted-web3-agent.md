# Week 1｜受限 Web3 助手——授权规则设计

> 课程：AI × Web3 School｜任务：设计一个「受限 Web3 助手」的授权规则清单  
> 完成日期：2026-05-20  
> 关联阅读：Bridge → Agent Wallet；AI 基础 → Agent

---

## 背景假设

给一个 AI Agent 一个 **EIP-4337 智能合约钱包的会话密钥（Session Key）**，让它协助日常链上操作（如查询余额、执行小额兑换、提供 DeFi 策略建议并执行）。

---

## 授权规则表

| 维度 | 规则 | 理由 |
|------|------|------|
| 最大单笔金额 | 500 USDC / 笔；日累计上限 1000 USDC | 单笔损失可接受；日上限防止被连续调用榨干 |
| 可调用合约白名单 | Uniswap V3 Router、Aave V3 Pool（主网 + Base）；其他地址一律拒绝 | 只和经过多轮审计的头部协议交互；新合约必须人工加白 |
| 禁止操作类型 | ① `approve` 无限额度（`type(uint256).max`）；② 任何跨链 Bridge 调用；③ 调用未验证合约（Etherscan 无源码） | 无限 approve = 永久敞口；Bridge 是最高风险操作；未验证合约来源不明 |
| 人工确认触发条件 | ① 单笔 > 200 USDC；② 目标合约不在白名单；③ 任何 `approve` 操作；④ 过去 1 小时内 Agent 已发起 3 笔以上交易 | 频率异常可能是被 Prompt Injection 操控；approve 风险独立于金额大小 |
| 紧急暂停机制 | 通过 Safe Multisig（2/3 签名）撤销该 Session Key；或调用 EIP-4337 钱包的 `revokeSessionKey()` 函数；热键操作在 30 秒内完成 | 不能依赖"联系客服"；撤销路径要比攻击路径短 |

---

## 核心安全假设

这套规则的底层假设是：**Agent 随时可能出错，无论是推理幻觉、工具调用被注入、还是上游 API 被劫持**，因此防线不能建在"相信 Agent 会做正确判断"上，而要建在"执行层强制拦截"上。白名单和金额上限是最后的物理屏障——即便 Agent 被完全欺骗，它能造成的最大损失也被限定在一个我可以承受的范围内。"最小权限"不是不信任 Agent，而是在信任失效时保护自己。

---

## 设计参考

- **ERC-8196 草案**：以太坊正在推进的 AI Agent 钱包策略标准，提出三层信任栈（注册 → 风险评分 → 策略执行），和本设计的分层防线思路一致
- **Elytro 智能账户**：EIP-4337 实现案例，支持链上 2FA + 美元日消费上限，印证了"链上规则优于链下承诺"的方向
- **OKX Agentic Wallet**：生产级实现，内置交易模拟和风险分级；本设计的"人工确认触发条件"参考了类似的风险评分逻辑

## 我如何辅助完成、又如何复核

1. **辅助方式**：用大模型搜集了 ERC-8196、Elytro、OKX Agentic Wallet 等真实项目作为参考依据
2. **复核方式**：每条规则都对应了今天 Handbook 学到的具体风险点（无限 approve 风险、Prompt Injection、最小权限原则）；没有引入我没读过或没核实的概念
3. **原则**：规则背后的理由必须是我自己能讲清楚的，不是填数字凑表格
