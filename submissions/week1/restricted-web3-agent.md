# Week 1｜受限 Web3 助手——授权规则设计

> 课程：AI × Web3 School｜任务：设计一个「受限 Web3 助手」的授权规则清单  
> 完成日期：2026-05-20  
> 关联阅读：Bridge → Agent Wallet；AI 基础 → Agent

---

## 要解决的问题

普通用户想用 AI 辅助链上操作（查询余额、执行小额兑换、执行 DeFi 策略），但又担心 AI 幻觉、被 Prompt Injection 操控、或 API 被劫持导致资产损失。  
**核心矛盾**：AI 需要足够的执行权限才能有用，但权限越大失控风险越高。  
**目标**：设计一套授权规则，让 Agent 在明确边界内自动执行低风险操作，同时对高风险操作强制插入人工确认，把最大可能损失限定在用户可接受范围内。

---

## 背景假设

给一个 AI Agent 一个 **EIP-4337 智能合约钱包的会话密钥（Session Key）**，让它协助日常链上操作（如查询余额、执行小额兑换、提供 DeFi 策略建议并执行）。

---

## 授权规则表

| 维度 | 规则 | 理由 |
|------|------|------|
| 最大单笔金额 | 500 USDC / 笔；日累计上限 1000 USDC | 单笔损失可接受；日上限防止被连续调用榨干 |
| 可调用合约白名单 | Uniswap V3 Router、Aave V3 Pool（主网 + Base）；其他地址一律拒绝 | 只和经过多轮审计的头部协议交互；新合约必须人工加白 |
| 禁止操作类型 | ① `approve` 无限额度（`type(uint256).max`）；② 任何跨链 Bridge 调用；③ 调用未验证合约（Etherscan 无源码） | 无限 approve = 永久敞口；Bridge 是最高风险操作；未验证合约来源不明 |
| 人工确认触发条件 | ① 单笔 > 200 USDC；② 目标合约不在白名单；③ 任何 `approve` 操作；④ 过去 1 小时内 Agent 已发起 3 笔以上交易 | 频率异常可能是被 Prompt Injection 操控；approve 风险独立于金额大小 |
| 紧急暂停机制 | 通过 Safe Multisig（2/3 签名）撤销该 Session Key；或调用 EIP-4337 钱包的 `revokeSessionKey()` 函数；热键操作在 30 秒内完成 | 不能依赖"联系客服"；撤销路径要比攻击路径短 |

## Workflow：输入 → AI 做什么 → 链上步骤 → 输出

```
用户输入
  └─ 自然语言指令，例如："帮我把 100 USDC 换成 ETH"
         │
         ▼
   AI / Agent 层（只做推理，不碰私钥）
   ① 解析意图，识别操作类型（swap / approve / query）
   ② 读取链上状态：当前余额、Uniswap 报价、gas 估算
      （工具调用 ethers.js，结果附 block number）
   ③ 检查授权规则：金额是否超限？合约是否在白名单？
   ④ 生成交易草稿（calldata + 预期 gas），交给执行层
         │
         ▼
   人工确认节点（满足任一条件则暂停，等用户确认）
   • 单笔 > 200 USDC
   • 目标合约不在白名单
   • 任何 approve 操作
   • 过去 1 小时已发起 3 笔以上交易
         │
         ▼
   Web3 执行层（需用户签名或已在限额内自动执行）
   ⑤ EIP-4337 钱包通过 Session Key 签名并广播交易
   ⑥ 等待区块确认（1–2 个区块）
         │
         ▼
输出
  └─ 交易哈希 + Etherscan 链接 + 实际成交金额 + 日累计消耗额度
```

**输入示例**：`"帮我把 100 USDC 换成 ETH，滑点不超过 0.5%"`  
**输出示例**：
```
✅ 已执行
交易哈希：0xabc123...（Etherscan 链接）
成交：100 USDC → 0.0412 ETH（实际滑点 0.31%）
Gas 消耗：0.0008 ETH
今日已用额度：100 / 1000 USDC
```

**被拦截示例**（输入 `"帮我把 600 USDC 换成 ETH"`）：
```
⚠️ 需要人工确认
原因：单笔金额（600 USDC）超过自动执行上限（200 USDC）
操作草稿已生成，等待你确认后执行。[确认] [取消]
```

## 核心安全假设

这套规则的底层假设是：**Agent 随时可能出错，无论是推理幻觉、工具调用被注入、还是上游 API 被劫持**，因此防线不能建在"相信 Agent 会做正确判断"上，而要建在"执行层强制拦截"上。白名单和金额上限是最后的物理屏障——即便 Agent 被完全欺骗，它能造成的最大损失也被限定在一个我可以承受的范围内。"最小权限"不是不信任 Agent，而是在信任失效时保护自己。

---

## 风险与限制

| # | 风险 / 限制 | 说明 |
|---|------------|------|
| 1 | **Prompt Injection** | 恶意网页或工具返回值可能注入指令，诱导 Agent 构造高风险交易。缓解：执行层白名单是最后防线，不依赖 Agent 的判断 |
| 2 | **链上状态时效性** | Agent 读取的余额、报价在交易广播时可能已过期（几个区块）。缓解：交易草稿附 block number，用户确认时提示数据时效 |
| 3 | **Session Key 泄露** | Session Key 如果被盗，攻击者可在白名单范围内自动执行操作直到日上限耗尽。缓解：日累计上限 + 紧急撤销路径（30 秒内） |
| 4 | **白名单协议自身漏洞** | Uniswap、Aave 曾出现过漏洞；白名单只能降低攻击面，不能消除协议层风险 |
| 5 | **AI 推理错误（幻觉）** | Agent 可能误解用户意图，例如把"买 ETH"解释成"卖 ETH"。缓解：输出草稿前展示"操作摘要"让用户二次确认 |

---

## 如何验证执行结果

1. **交易哈希核查**：每笔操作返回完整交易哈希，可在 Etherscan 独立验证成交金额、接收地址、合约地址是否与草稿一致
2. **余额前后对比**：Agent 在执行前读取余额（附 block number），执行后再次读取，两次数据可独立复现
3. **日志可审计**：每条链上操作记录「意图 → 草稿 → 是否人工确认 → 交易哈希 → 最终状态」，日志本地存储，不含私钥
4. **撤销验证**：通过 `revokeSessionKey()` 后，原 Session Key 发出的任何交易应被 bundler 拒绝，可在测试网验证

## 设计参考

- **ERC-8196 草案**：以太坊正在推进的 AI Agent 钱包策略标准，提出三层信任栈（注册 → 风险评分 → 策略执行），和本设计的分层防线思路一致
- **Elytro 智能账户**：EIP-4337 实现案例，支持链上 2FA + 美元日消费上限，印证了"链上规则优于链下承诺"的方向
- **OKX Agentic Wallet**：生产级实现，内置交易模拟和风险分级；本设计的"人工确认触发条件"参考了类似的风险评分逻辑
